  <what-built>
    Plan 01 replaced the shared singleton embedded browser with a per-project
    WebContentsView registry; plan 02 wired project identity through the studio so each
    project tab drives only its own browser view and path state.
  </what-built>
  <how-to-verify>
    1. Start the app: `pnpm dev` (Electron window opens; wait for splash to finish)
    2. Open the projects view. Ensure TWO projects exist (edit defaults or create a second
       via "Create New Project & Target URL"). Give them DIFFERENT target URLs, e.g.:
       - Project A: `https://example.com`
       - Project B: `https://www.wikipedia.org`
    3. Open Project A studio. Wait for the embedded browser to load example.com.
       In the studio URL bar, navigate to a path/page (e.g. `example.org` via the bar or a link).
    4. Switch to Project B (project tab in the header). EXPECTED: the embedded browser shows
       wikipedia.org (project B's own URL), NOT the page you navigated to in project A.
       The URL bar must not show project A's last address.
    5. Switch back to Project A. EXPECTED: its browser shows the page you navigated to in
       step 3 (per-project view survives switching; no reload flicker if URL unchanged).
    6. In Project B, edit its target URL via the project edit modal to another URL and save.
       Switch to Project A: EXPECTED unchanged (bug repro check — the original defect was
       "changing the url of 1 project changes every other project").
    7. Close Project B's tab, reopen it: browser loads B's target URL fresh, A unaffected.

    FAIL criteria: any step shows another project's URL/page, blank white view that never
    loads, or console errors from webviewManager — report which step failed.
  </how-to-verify>
