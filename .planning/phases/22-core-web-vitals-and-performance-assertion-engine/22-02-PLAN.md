  <behavior>
    - Test 1: CLI runner attaches PerfObserverEngine to BrowserContext and applies frontmatter/CLI throttling presets before executing steps.
    - Test 2: CLI runner executes `assertPerformance` steps, evaluates against WebVitalsMetrics, and fails flow if budget is violated (or warns if warnOnly).
    - Test 3: CLI runner executes `throttle` step dynamically modifying network/CPU conditions on Chromium and safely bypassing on Firefox/WebKit.
    - Test 4: CLI runner captures end-of-flow WebVitalsMetrics and includes performance telemetry in `matrix-report.json`.
    - Test 5: Electron PlaywrightEngine supports `assertPerformance` and `throttle` steps, streaming live performance metric logs to the renderer.
  </behavior>
  <action>
1. Update `cli/runner.ts`:
   - Import `PerfObserverEngine`, `evaluatePerformanceAssertion` from `../electron/core/perf/perfObserverEngine.js`.
   - Update `normalizeStep`:
     - Support `assertPerformance` and `assert_performance`:
       ```typescript
       if (key === 'assertPerformance' || key === 'assert_performance') {
         return { action: 'assertPerformance', ...(typeof val === 'object' && val !== null ? val : {}), ...rest };
       }
       if (key === 'throttle') {
         return { action: 'throttle', ...(typeof val === 'object' && val !== null ? val : { preset: val }), ...rest };
       }
       ```
   - Update `executeSingleFlow`:
     - Initialize `const perfEngine = new PerfObserverEngine();`.
     - Call `await perfEngine.attachToContext(context, browserName);`.
     - Apply flow-level throttling if defined in `flowJson.throttling` or `options.throttle`:
       - `await perfEngine.applyThrottling(page, flowJson.throttling || options.throttle, browserName);`.
     - In step execution loop:
       - Handle `normalized.action === 'throttle'`:
         - Apply network/CPU throttling config via `await perfEngine.applyThrottling(page, normalized, browserName);`.
         - Record step as passed.
       - Handle `normalized.action === 'assertPerformance'`:
         - Harvest current metrics: `const metrics = await perfEngine.harvestMetrics(page, browserName);`.
         - Evaluate: `const evalRes = evaluatePerformanceAssertion(metrics, normalized, normalized.warnOnly);`.
         - If `!evalRes.passed && !normalized.warnOnly`:
           - Set `flowStatus = 'failed'`.
           - Record step as failed with `error: evalRes.summary`.
           - Break or continue based on flow metadata.
         - Else:
           - Record step as passed with `perfResult: evalRes`.
     - At end of flow execution:
       - Harvest final metrics: `const finalMetrics = await perfEngine.harvestMetrics(page, browserName);`.
       - Evaluate flow-level `performanceBudget` if defined in `flowJson.performanceBudget`.
       - Populate `metrics: finalMetrics` on the returned `CliTestResult`.
2. Update `electron/ipc/playwrightEngine.ts`:
   - Initialize `PerfObserverEngine` when launching flow context.
   - Handle `assertPerformance` and `throttle` step commands in `run_flow` switch case.
   - Stream telemetry to renderer via `execution-log` with metric breakdowns.
   - Clean up throttling on flow finish in `finally` block.
3. Update tests in `cli/runner.test.ts` and `electron/ipc/playwrightEngine.test.ts`:
   - Test flow with `assertPerformance` step passing with good metrics.
   - Test flow with `assertPerformance` step failing when metric threshold is exceeded.
   - Test cross-browser fallback on Firefox/WebKit targets without CDP errors.
   - Test `throttle` step execution.
  </action>
