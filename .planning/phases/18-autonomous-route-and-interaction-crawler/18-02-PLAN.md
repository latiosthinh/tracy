  <behavior>
    - Test 1: Explores within origin boundaries; external links (different hostname or port) are rejected.
    - Test 2: Uses (normalizedUrl, skeletonHash) state tracking to avoid infinite loops across dynamic SPA views and pagination.
    - Test 3: Respects maxDepth and maxPages configuration limits.
    - Test 4: Emits progress callbacks on each discovered node and edge.
  </behavior>
  <action>
1. Create `electron/core/crawler/bfsCrawler.ts`:
   - Class `BfsCrawler` accepting `CrawlOptions` and optional Playwright `Page` or mock browser provider.
   - Maintain `visitedStates: Set<string>` keying on `${normalizeUrl(url)}::${skeletonHash}`.
   - Maintain `crawlGraph: { nodes: Map<string, CrawlNode>; edges: CrawlEdge[] }`.
   - Maintain queue: `Array<{ url: string; depth: number; pathSoFar: CrawlEdge[]; previousNodeId?: string }>`.
   - In crawl step:
     a. Navigate to target URL.
     b. Wait for network/DOM load.
     c. Extract structural skeleton and compute hash via `computeDomSkeletonHash`.
     d. Build `CrawlNode` and store in graph.
     e. Extract interactive elements (`<a>`, `<button>`, `<form>`).
     f. Filter safe elements using `filterSafeInteractiveElements`.
     g. If depth < maxDepth and totalNodes < maxPages:
        - For links: add matching internal URLs to queue.
        - For forms: if `options.fillForms`, plan safe inputs via `planFormInteractions` and record edge.
        - For buttons: simulate safe click to detect SPA route change or state expansion.
     h. Emit progress callback (`CrawlProgressEvent`).
   - Implement graceful cancellation via `abortController`.

2. Write comprehensive unit tests in `electron/core/crawler/bfsCrawler.test.ts` using mocked page/DOM structures.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer -> Main Process IPC | Renderer initiates crawl requests with user-specified target URL and crawl options. |
| Crawler -> Target External Sites | Crawler makes HTTP/WebSocket requests and renders pages in Playwright. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-04 | Spoofing / Tampering | `crawlerIpc.ts` | mitigate | Validate start URL scheme (only http/https allowed) before launching crawler. |
| T-18-05 | Denial of Service | `bfsCrawler.ts` | mitigate | Enforce maxPages (default: 50, max: 200), maxDepth (default: 3, max: 10), and timeout bounds to prevent memory/CPU starvation. |
| T-18-06 | Elevation of Privilege | `preload.ts` | mitigate | Explicitly whitelist `start_crawl`, `stop_crawl`, `generate_crawl_flows`, and `crawler_progress` in IPC security filters. |
</threat_model>
