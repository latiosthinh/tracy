## Commands

Package manager is **pnpm**.

| Task | Command |
|---|---|
| Dev (Vite + Electron) | `pnpm dev` |
| Type check | `pnpm typecheck` (= `tsc --noEmit`) |
| Lint | `pnpm lint` (= `eslint . && tsc --noEmit`) |
| Test | `pnpm test` (Vitest, single run) |
| Test (watch) | `pnpm test:watch` |
| Single test file | `pnpm test path/to/file.test.ts` |
| Full build | `pnpm build` (= `tsc && vite build && electron-builder`) |
| Clean artifacts | `pnpm clean` (removes `dist`, `dist-electron`, `release`) |

Run `pnpm lint` and `pnpm test` before considering any change done. `unused-imports/no-unused-imports` is an ESLint **error** and will fail CI; `@typescript-eslint/no-explicit-any` is a warning.

## Architecture Overview

Tracy is a desktop E2E browser testing IDE powered by Electron, React 19, Vite, Playwright, and Google GenAI. It's a dual-process app. See `docs/ARCHITECTURE.md`, `docs/FLOW_SCHEMA.md`, and `docs/DOM_MINER.md` for deep dives.

### Electron main process (`electron/`)

- `main.ts`: Process entry point and window management.
- `preload.ts`: Exposes the secure IPC bridge (`window.tracyAPI`) to the renderer. Contains channel whitelists (`ALLOWED_INVOKE_CHANNELS` / `ALLOWED_ON_CHANNELS`) — any new IPC channel must be added here **and** in the `tracyApi` wrapper in `src/lib/ipc.ts`.
- `ipc/`: Backend implementation modules for IPC calls:
  - `playwrightEngine.ts`: Embedded Playwright engine executing E2E YAML flows against live browsers and streaming logs/screenshots back to the UI.
  - `webviewManager.ts`: Manages embedded webview sessions and element inspection.
  - `fileSystem.ts`: Handles local project file operations and YAML serialization.
  - `aiProvider.ts`: Multi-provider AI abstraction layer (Gemini, OpenAI-compatible endpoints). Factory pattern — each provider returns a common `AiProvider` interface.

### React renderer (`src/`)

- `lib/ipc.ts`: Type-safe client wrapper mapping `window.tracyAPI` IPC channels. Every method has an `isElectronEnv()` guard returning safe defaults (empty arrays, empty strings, null) so the renderer can also run in browser-only mode via Vite.
- `stores/`: Modular Zustand stores for application state:
  - `projectStore.ts`: Projects, active YAML test flows, auto-saving.
  - `executionStore.ts`: Playwright runner execution status, timelines, real-time logs.
  - `domSnapshotStore.ts`: DOM syntax trees generated by `dom-miner`.
  - `uiStore.ts`, `settingsStore.ts`, `agentStore.ts`: Layout, user preferences, and AI agent configuration.
- `components/`:
  - `studio/`: Integrated test studio (`StudioView.tsx`), live browser display (`RealBrowserView.tsx`), step timelines, and element inspector.
  - `editor/`: Text YAML editor and `VisualStepEditor.tsx`.
  - `ai/`: AI Copilot integration (`AiCopilot.tsx`) using Google GenAI SDK to generate or refine test flows.
  - `reports/`: Execution logs and terminal output.
- `a11y/`: Accessibility translation dictionary (`en.json`). Screen readers, tab navigation, and tooltips are first-class requirements — all user-facing labels flow through this dictionary.
- `types/`: Shared TypeScript types organized by domain (`autoflow.ts`, `flow.ts`, `execution.ts`, `project.ts`, `ui.ts`, `uiSettings.ts`).

### DOM Miner & AI layer

Page DOM is captured and compressed via `dom-miner` (`src/utils/domMiner.ts`) into a token-optimized syntax tree, then fed with natural-language prompts to the AI layer (`@google/genai`) to synthesize YAML test steps conforming to `docs/FLOW_SCHEMA.md`.

### Tests

Vitest + Testing Library, `jsdom` environment, globals enabled. Test files are colocated as `*.test.ts(x)` next to their source — patterns: `src/**/*.test.{ts,tsx}`, `electron/**/*.test.ts`. Setup file: `src/test/setup.ts` (imports `@testing-library/jest-dom/vitest`).

## Key Conventions

- **Path alias**: `@/*` resolves to the repo root (configured in `tsconfig.json`, `vite.config.ts`, and `vitest.config.ts`). Use `@/src/...` for renderer imports.
- **IPC contract**: any new channel must be added in BOTH `electron/preload.ts` whitelists AND the `tracyApi` wrapper in `src/lib/ipc.ts`.
- **Main-process externals**: Node-only packages must be added to `MAIN_PROCESS_EXTERNALS` in `vite.config.ts` (regex list covering `playwright-core`, `chromium-bidi`, `playwright`, `js-yaml`, `@google/genai`; applied to both `rolldownOptions` and `rollupOptions`).
- **Tailwind v4**: CSS-first theming via `@tailwindcss/vite`; there is no `tailwind.config.js`.
- **ESLint**: `unused-imports/no-unused-imports` is an **error** (will fail CI). `@typescript-eslint/no-explicit-any` is a warning.
- **HMR toggle**: Setting `DISABLE_HMR=true` disables Vite HMR + file watching (used during AI agent edits to prevent flickering). Do not remove this logic from `vite.config.ts`.

## YAML Flow Schema

Test flows are YAML files with a comment-based title line, optional `url:` frontmatter, and a list of steps. The supported actions are: `navigate`, `leftClick`, `rightClick`, `hover`, `scroll`, `tap`, `twoFingersTap`, `press`, `fill`, `waitFor`. Each step can carry attributes: `selector` (CSS/XPath), `text`, `key`, and `timeout`. Full schema details are in `docs/FLOW_SCHEMA.md`.

The `YamlEditor` understands this schema and provides `Ctrl+Space` AI-assisted autocomplete for actions and attributes based on cursor indentation.

## Security Constraints (Electron)

The `BrowserWindow` is created with `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`. All privileged operations must go through the IPC bridge — never bypass this by enabling `nodeIntegration` or disabling `contextIsolation`.

## GSD Plan Execution — ALWAYS delegate to agent

When a plan needs to be implemented (PLAN.md, phase plans, GSD phases):

**DO NOT execute plans directly in this session.** Instead, spawn the `gsd-executor` agent:

```
Agent(description: "execute-phase-X-Y", prompt: "Execute the plan at .planning/phases/X-name/phase-X-Y-PLAN.md ... rest of context ...", subagent_type: "gsd-executor")
```

Always use `subagent_type: "gsd-executor"`. Do not attempt to implement GSD plans inline.

This rule applies to every phase execution request — always route through gsd-executor.
